# Web 模块与交互状态设计

更新日期：2026-11-04。状态：逻辑与 M1 交互状态设计草案。本文展开[整体架构](../architecture.md)中的 Web，供前端实现者和交互审阅者使用，承接 R01、R03—R05、R07—R17 及 Q01—Q05、Q07、Q10、Q11。M1 推荐 Vue 3／TypeScript，布局和组件库尚未决定。

## 1. 内部组成和状态归属

| 部分 | 维护的状态 | 依赖与边界 |
| --- | --- | --- |
| 身份与能力 | 登录用户、当前授权摘要、会话失效 | 从 Manager 获取；按钮显示不能代替后端授权 |
| 导航上下文 | 当前节点、资源标识、视图及筛选条件 | 操作生成明确目标，不从页面名称临时推导 |
| 查询与缓存 | 节点／资源结果、采集时间、请求代次、错误 | 缓存键包含用户与节点；不能跨账号复用秘密内容 |
| 配置编辑 | 打开版本、文件集合、草稿、脏状态、诊断和保存冲突 | 保存交给配置接口；草稿不改变已提交部署输入 |
| 操作提交与订阅 | 提交标识、operation_id、快照及事件位置 | 使用持久操作恢复；不由动画推定成功 |
| 诊断会话 | 日志／统计／控制台连接及目标 | 独立权限与生命周期，切换对象要关闭 |
| 命令转换 | 输入、生成配置、未映射项和依赖 | 只调用文本转换，不自动访问节点或部署 |

身份、导航和查询位于公共状态范围；每份配置编辑会话保留独立上下文，避免节点切换把 A 的内容保存到 B。操作结果来自 Manager，资源当前状态来自带时间查询，两者可以不同。

## 2. 切换节点与异步响应

发起查询时捕获用户、节点、资源和请求代次。返回后仅在匹配上下文时更新当前视图；旧请求可留在其正确缓存项，不能覆盖新节点。取消浏览器请求只是减少无用工作，不能替代响应归属检查。

修改操作从点击到确认都持有不可变目标。确认界面显示节点、对象和影响；如果用户改变目标，需要重新构造确认，不能让已打开的删除确认跟随全局节点变化。登出或账号切换清除受限缓存和诊断会话。

节点离线、查询失败、权限不足、确实无资源分别展示。历史快照附时间和来源；Manager 可达而 Agent 不可达时，仍可读获准的已保存配置，但不能把历史快照当当前健康。

## 3. 编辑、保存与部署

编辑器保存文件集合原文和文件顺序，显示当前基准版本及是否存在未保存修改。离开时提供留在编辑器或放弃的明确选择。M1 建议配置草稿仅在内存中保留，刷新前提醒未保存内容会丢失；不把配置或环境值写入浏览器长期存储。长期草稿功能的保存期限与秘密处理留待单独审阅。

保存附基准版本。成功后以返回的新版本更新基准；冲突时保留本地草稿和服务端新版本供对比，不自动覆盖或替换草稿。语法校验与目标原生预检分开，编辑器可解析不代表目标可部署。

部署明确选择已保存版本。存在未保存修改时，提示先保存或明确部署原已保存版本，不能默默选一边。提交后记录 operation_id，继续编辑只生成新草稿，不改变该部署的输入。界面区分最新保存版本、最近成功部署版本、最新尝试及当前资源观察。

## 4. 提交超时、结果订阅和重连

发起变更前生成并保留提交标识。响应超时后使用该标识核对是否已受理；不能生成新标识直接重做。若尚无法确定，显示待核对并限制冲突变更。

M1 收到操作标识后轮询权威快照，不依赖推送。后续启用事件订阅时，事件包括操作标识和有序位置；重复事件只合并一次，发现缺口或无法继续订阅时重新读取快照，事件格式和断点窗口另行细化。浏览器重开可通过操作记录恢复结果，恢复本身不再次提交。

成功显示遵守[数据状态](../data-design.md)：执行成功、资源观察和业务确认分别显示；迁移验证和来源清理也分别显示。未知不使用失败提示诱导用户立即重试，取消按钮要说明只是请求而非保证回滚。

## 5. Copy、迁移与来源处理

Copy 展示来源版本、目标配置、文件与外部依赖，允许明确修改目标配置。完成后进入独立目标编辑，可再发起 Apply。来源离线时说明配置来自已保存版本，不推断来源运行状态。

迁移流程呈现准备、数据准备、切换、验证和来源选择，但尚未确定的切换动作不提供虚构的可执行步骤。验证项目逐项显示机器证据和人工确认，不以一个绿色状态代替业务核对。只有有效验证及授权允许时，才进入独立来源清理确认；显示配置、资源和数据分别会受何影响。

来源发生重新部署或目标不再满足接替条件时，旧验证不能继续支持清理。清理失败显示局部结果与后续核对入口，不回到迁移第一步自动重跑。完整行为依[功能设计](../functional-design.md#7-node-cross-迁移)和 O05 确定。

## 6. 诊断、转换与权限变化

日志、统计和控制台各自检查能力，创建时固定节点和资源。切换对象、登出、权限失效或资源消失后关闭对应会话；重连重新授权，不无条件续接旧终端。不能让只读列表权限附带控制台执行能力。

转换工具显示原命令、生成的可编辑配置、映射与未转换项、外部依赖及语义差异。存在未解决项时明确标注，带入编辑器仍是草稿；保存和部署另外选择目标与授权。服务端无法解析时保留输入，不执行它来取得值。

权限变化可能使当前编辑内容不可再次读取；Web 停止后续受限请求并处理缓存和流，已保存或执行事实由 Manager 记录。用户需要保留的工作与秘密清理规则随 O07 裁定，不能用前端状态推定后端已撤销任务。

## 7. 实现接入与验证

第 8 节将状态责任映射为 M1 的路由和组件建议；不要求一项责任对应一个独立页面。先实现身份／节点上下文，再连接配置条件保存和持久操作查询，最后增加诊断流和转换工具，保持同一目标标识规则。

关键验证：两个节点同名对象、A 的慢响应晚于 B、保存冲突、提交响应丢失、事件缺口、登出后缓存、跨节点撤权及清理验证失效。见 T02、T03、T05、T07、T09、T14、T15。本文沿 [arc42 构件](https://docs.arc42.org/section-5/)与[运行](https://docs.arc42.org/section-6/)展开前端内部协作，界面需求继续回到 req42 所组织的[需求规格](../requirements.md)。

## 8. M1 路由、组件与状态转换

以下是 P07／P08／P10 的实现建议，页面 URL 与 Manager 的 API 路由分别维护，不因名字相似共用权限判断。Web 构建静态产物后由 Manager 同源交付；不在前端存放 Agent token 或管理端加密密钥。

| 页面路由建议 | 组件与状态责任 | 当前范围 |
| --- | --- | --- |
| `/login` | LoginForm、SessionStore；取得服务端会话和当前能力 | 本地账号登录、失效与重新认证 |
| `/nodes` | NodeList；独立展示连接、Docker／Compose 能力及最近观察 | 获准节点列表、接入状态；分类编辑在 M2 |
| `/nodes/:nodeId/stacks/:stackId` | StackContext、FileEditor、VersionBar、ApplyPanel | 新建／编辑文件、条件保存、固定版本部署与当前观察 |
| `/operations/:operationId` | OperationSummary、CommandResult、ResourceObservation | 状态、取消请求、失败和核对；原始输出独立授权 |
| `/settings/access` | AccountList、NodeGrants、EnrollmentPanel | 管理账号及明确节点授权、一次性接入材料；system.admin 不隐式代表可部署 |

所有节点内页面先加载权限与对象归属，失败时不能使用上次节点的缓存补出可操作界面。查询键为 `(user_id, auth_rev, node_id, resource_kind, resource_id)`，每次请求另带本地 generation；响应必须与发起上下文匹配。权限摘要用于展示，后端始终复核。

### 8.1 编辑会话与冲突恢复

HTTP 对象、权限裁剪、分页和完整错误定义采用 [HTTP 工作规格](../specifications/http-api.md)。同一编辑会话只允许一个保存请求在途；期间允许继续编辑，但第二次保存暂不可提交。超时先查原 key，成功后才以新版本继续保存，不能让两个不同草稿以同一基准并发写入。内部组件和临时编辑类型仍由实现决定。

一个编辑会话持有 `node_id`、`stack_id`、打开版本、服务端 ETag、文件原文、有序文件列表、环境、编辑代次和保存请求 key。API config 使用 `files`、`compose_files`、`interpolation_env_files`、`interpolation_env`、`profiles`；文件原文按 `content_b64` 运输。保存点击时复制出不可变请求，随后继续输入只修改下一份草稿。保存成功时仅在编辑代次未变化时清除脏标志；已经继续输入则更新基准但保留新增修改，不能用返回正文覆盖它。

| 状态与刺激 | 界面行为 | 后续请求规则 |
| --- | --- | --- |
| clean → 编辑 | 进入 dirty，标记未保存；部署仍只能选已保存版本 | 不自动调用 Apply |
| dirty → 保存 | 保存冻结请求，进入 saving；允许继续编辑并区分在途版本 | If-Match 和幂等 key 均属于冻结请求 |
| saving → 成功 | 显示新版本；按编辑代次决定 clean 或 dirty | 更新服务端 ETag，保留之后的本地改动 |
| saving → 版本冲突 | 保留草稿，显示基准／服务端新版／本地内容的文件级差异 | 用户选取或手工合并后用新基准和新 key 保存；没有隐式强制覆盖 |
| saving → 网络超时 | 显示保存结果待确认，保留原请求 | 查同 key 的写入回执；未查到可重发完全相同请求，不能先换 key |
| 任意 → 401 | 暂停请求和提交，进入重新认证 | 身份确认前不恢复敏感读取；账号变化清空旧编辑会话 |
| 任意 → 403／账号禁用 | 清除受限正文、草稿及缓存，说明权限已变化 | 不提供绕过授权的本地导出；先前已保存版本仍由 Manager 管理 |
| 受限查询 → 404 | 清除对应对象正文、草稿及缓存，显示“对象不可用或无权访问” | 不区分撤权与对象不存在，不用旧缓存回退展示；如为节点范围失效则清除整个节点上下文 |

仅允许按 UTF-8 原文编辑 M1 支持的文件；包大小与路径规则从接口契约取得。校验诊断指出文件和字段，编辑器不能自行修复或删除不支持的 Compose 字段。保存成功与部署准备成功分别标注。

权限失效处理同时递增本地请求 generation 并关闭对应订阅；在此之后才到达的旧成功响应不能把已清除的正文重新写回。节点详情及会话复核发现 auth_rev 改变时使旧权限缓存失效，后续请求按新权限执行；不承诺能从用户已经看过或另存的内容中撤回信息。

### 8.2 提交记录与操作展示

提交 Apply 前固定节点、Stack、version_id 和项目名称，展示“此次部署版本”。部署需要 `node.read`、`config.read` 与 `stack.deploy`；完整命令输出另需 `operation.output.read`，任务摘要不得夹带原始配置。含未保存内容时提供“先保存”或“部署已保存版本”两个明确动作。

`sessionStorage` 只保存当前用户的提交 key、目标 ID、版本 ID 与返回的 operation_id，不能包含文件正文、环境值、Cookie、输出或令牌；登出时删除。刷新后先查询 `/api/v1/submissions/{idempotency_key}` 回执或操作，配置草稿丢失不意味着重新提交。无回执或请求仍在途时不能推定服务器绝对没有执行；允许原 key、原输入的幂等重发，输入已丢失则停留待核对。

建议前台活动操作每 2 秒轮询一次，页面后台每 10 秒；节点列表每 15 秒。请求不重叠，退避需有上限并显示最后成功时刻；完成后停止任务轮询，资源观察独立刷新。参数是候选流量预算，M0／O08 用慢网与多用户验证。快照只按新版本更新，不让迟到的旧快照把 succeeded 覆盖回 running。

结果区分别显示：受理与授权阶段、命令退出或中断、部署输入版本、资源观察及采集时间。使用 OperationResult 的 outcome、ownership_status 和 observation，不能只看 exit_code。终态但 release_status=pending 显示“结果已确认，释放待确认”，不暗示可以重新变更；后端仍复核占用。reconciliation_required 显示“需核对”及已有证据；M1 不提供无条件“强制解锁重跑”按钮。取消在已发许可或已开始后显示“已请求取消，结果待核对”，不能即时改为 canceled。具有部署权而没有 operation.read 时仅显示受理回执及无结果查看权限，不循环轮询403。

### 8.3 会话和工程接入

同源请求携带受保护 Cookie，变更请求加 CSRF token；登录／登出／账号禁用后由服务器使会话失效，Web 清理受限状态。M1 不把 Cookie 换成 localStorage 中的 bearer，也不将服务端错误详情原样注入 HTML。接口返回的文本诊断作为文本展示。

建议未来目录为 `web/src/features/{session,nodes,stacks,operations,access}` 与共用 `api/`、`components/`。API 层集中处理认证、请求 key、错误映射及快照校验；编辑器不自行拼接部署请求，OperationStore 不修改编辑内容。当前没有这些代码文件。将来引入事件流时替换的是更新来源，不改写持久 operation_id 和权限规则。
