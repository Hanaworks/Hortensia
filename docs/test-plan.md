# Docker Manager 测试计划

更新日期：2026-11-07。状态：测试方案与M0／M1验证规格；M0通信与独立许可门禁、Agent开始账本、事件／首结果日志、Manager本地持久协调及Agent本地恢复扫描切片已完成；本轮实现Manager扫描接收与业务恢复，逐项结果与证据见[本轮验收记录](implementation/m0-manager-recovery.md)。完整产品测试尚未执行。本文供实现者和测试执行者使用，持续承接req42所组织的[需求与成功标准](requirements.md)，以及arc42所组织的[运行、质量与风险](architecture.md)。文档检查不能替代下列软件验证。

## 1. 验证目标与分层

验证重点是操作作用于正确节点和对象、配置与原生 Compose 一致、权限有效、未知结果可恢复核对，以及迁移验证与来源删除不被混淆。正常路径与拒绝路径都要检查实际资源副作用，不能只断言返回状态。

| 层次 | 对象和方法 | 能支持的结论 |
| --- | --- | --- |
| 逻辑单元 | 条件保存、权限判断、输入映射、操作／验证状态与不变量 | 局部规则符合规格，不能证明真实节点工作正常 |
| 契约 | Web—Manager、Manager—Agent 的标识、错误、重报、事件和授权 | 双方对同一操作含义一致，不代替真实执行 |
| 集成 | 实际存储、CLI／Engine、文件工作区、进程与节点通道 | 实现与外部依赖正确衔接 |
| 端到端 | 受支持部署环境中用不同账号操作两节点 | 完整流程及权限有效 |
| 故障与规模 | 断线、崩溃、迟到重复、账本异常、约 20 节点 | 指定条件下的恢复及性能证据，不外推任意规模 |

## 2. 环境、数据和执行前提

准备两个可独立控制、资源相互区分的 Docker 节点 A／B，以及只对 A 具有权限的账号、配置维护但无部署权限的账号和可执行跨节点流程的账号。使用可丢弃测试资源，保存初始快照。测试命令和镜像按环境记录，不操作真实业务数据。

记录 Manager／Agent 版本、协议、操作系统、Agent 所在环境、Docker 端点位置、Engine／Compose 版本、文件目录、项目参数、镜像标识和网络条件。Linux、FreeBSD 的用户意向不是已通过的环境矩阵；只有实际运行组合通过后才列为支持。

准备单／多文件 Compose、不同环境来源、附属运行文件、外部卷／网络、绑定路径、缺镜像及 build 依赖等材料。另备同名 Stack、旧操作、替换后的同名资源和权限撤销情况。带秘密的测试使用可辨认假值，以检查日志和导出是否泄漏。

## 3. 核心用例与断言

以下全部为计划，尚无应用执行结果。

| 用例 | 设置与操作 | 必须观察的结果 |
| --- | --- | --- |
| T01 安装与账号 | 首个安装产物在已声明环境初始化、登录、禁用账号；验证重启 | 可完成初始化；禁用后受限请求拒绝；必要状态持久存在；具体步骤待产物出现 |
| T02 同名与节点切换 | A／B 同名 Stack，A 查询故意慢于 B；切换后查看、编辑并确认删除 | 旧响应不覆盖 B；确认目标保持固定；实际资源变化只发生于获准对象 |
| T03 编辑与版本 | 两人打开同版，先后保存；另提交部署后再保存下一版 | 后保存冲突保留草稿；已提交部署使用固定版本；最新保存不冒充最近已部署 |
| T04 原生语义 | 使用相同节点、CLI 版本、文件顺序、目录、环境和项目参数分别校验／部署 | 原生渲染关键字段和创建资源语义一致；默认网络可存在，管理器无额外注入；缺依赖明确错误，无意外构建 |
| T05 授权组合 | 同节点不同操作、不同节点权限、直接请求、Copy 两端和撤权 | 列表、正文、计数和变更均按权限；拒绝无副作用；仅有目标配置维护不能部署 |
| T06 Copy／Apply | 来源离线但配置完整；同标识重复 Copy、目标重名、Apply 失败 | 一份独立目标配置；冲突明确；Copy 与部署结果独立；来源版本和资源均未变 |
| T07 丢失与重报 | 受理后丢失 Web 响应；Agent 收到任务或回报后丢包，重复消息 | 原标识查到同一操作，Agent 不重复开始；事件可去重；无法确定时保留未知 |
| T08 崩溃边界 | 在持久受理、发送、许可、Agent 开始记录、进程创建、结果保存等位置重启双方 | 恢复已有结果或进入核对；未知副作用不以新标识重做；未结束占用不被默默释放 |
| T09 迁移验证门槛 | 模拟目标启动但来源仍活动、业务未确认、数据证据缺失或失联 | 不能标为已验证；不进入来源删除；机器观察与人工声明分别可见 |
| T10 完整迁移与失败矩阵 | O05 决定后在各切换阶段注入故障，覆盖保留来源、回退和未知 | 目标接替、来源活动状态、验证和来源选择符合策略；不能用 Copy 用例替代；当前尚不可执行 |
| T11 基础资源操作 | 创建／启停／删除独立容器、查日志统计、拉取镜像、网络和卷操作 | 目标和归属正确，错误与数据影响清楚；Stack 容器操作不伪造已修改 Compose |
| T12 已有资源 | 接入已有容器和不完整 Compose 项目，再尝试编辑、接管和跨节点 | 发现不改资源；配置不全可解释且不冒充完整；接管覆盖按 O10 明确后验证 |
| T13 命令转换 | 常见短长参数、引号、续行、变量、命令替换、未知参数、网络／卷／entrypoint | 支持参数映射正确，未支持及差异逐项可见；不执行输入、不读环境猜测、不创建资源 |
| T14 流与订阅 | 日志、统计、控制台断线、对象切换、撤权；操作事件重复与缺口 | 正确关闭和重授权，无跨对象混流；快照可补齐结果，不依赖永不丢失事件 |
| T15 清理与对象变化 | 验证通过后来源重启／同名对象被替换／目标变化，或撤销清理权限 | 旧验证不能继续支持清理；拒绝错误对象或无权限删除；清理失败不抹去迁移证据 |
| T16 备份恢复 | 活动记录存在时生成一致备份，在隔离环境恢复并重新核对节点 | 配置文件与元数据、身份与保护材料一致；旧任务不自动重放；应用数据未被误称已备份 |
| T17 路径与执行输入 | 越界路径、符号链接、缺失文件、远程 Docker 路径差异、进程环境污染、账本损坏 | 管理器不越界读写；不支持组合明确拒绝；摘要和工作区不符不执行；损坏后进入核对 |
| T18 分类与规模 | 约 20 个混合网络节点，含慢／离线节点，分组标签修改、筛选并操作健康节点 | 归类不移动或删除资源、不扩权；计数受限；记录负载、延迟与资源占用，按 O08 阈值判断性能 |

## 4. 原生对照与转换专项

T04 对照必须控制所有影响语义的输入，分别保存原始文件、CLI 命令参数、受控环境和渲染／资源结果。对照后清理测试资源，不能以资源名字完全相同替代关键语义比较，也不能把渲染文本格式差异当成行为差异。

T13 按支持清单分别检验每项参数及组合。`--entrypoint` 可能影响默认 CMD；外部命名卷和自定义网络不能被转换成新的项目资源；无值环境参数不能在转换器中偷偷取进程环境。不能等价的输入保留诊断。仅断言生成 YAML 能解析不足以证明转换正确。

## 7. M0／M1 验证规格

本节把既有 T 类用例细化成可交给原型执行者的实验。所有项仍为未执行。先按 P07—P10 在可丢弃 Linux 环境记录运行组合，再建立可注入暂停、丢包、进程终止与写盘失败的边界；不能在真实业务节点首次验证这些故障。

### 7.1 夹具与对照条件

| 夹具 | 具体组成 | 用途与记录 |
| --- | --- | --- |
| F01 多文件配置 | compose.yaml＋override.yaml；插值文件包含假值 `FIXTURE_SECRET_A`；应用 env_file 和只读配置文件；两个不同 profiles | 保存字节、文件顺序、插值映射与目录；确认编辑／保存／部署用同一版本 |
| F02 镜像与 Build | 一组 image+build 原文、一个缺 image 的有效服务、一份含可辨认标记的构建上下文 | 对照原生 `up --no-build`；不得出现实际构建记录，不通过日志中“没打印 build”推断 |
| F03 路径与依赖 | `../`／绝对包路径、重复文件、符号链接、include 外部引用、绝对 bind、外部命名网络／卷 | 区分包读写拒绝与应用合法绑定；缺依赖有位置明确的错误，不静默创建或改写配置 |
| F04 身份与权限 | A／B 两个节点；账号甲可读写 A 但不可部署，乙可部署 A，丙仅可见 B；另有显式授权管理员 | 验证跨节点、动作、输出和授权竞争，不把管理员隐式权限掩盖为通过 |
| F05 持久化故障 | 一份新库、一份待开始操作、一份 START_COMMITTED、一份已完成未 ack、两代 HMAC 密钥 | 验证事务、输出重报、旧键重试、恢复隔离与去重证据保留 |

镜像必须记录实际 digest／image ID，端口和项目名限定在隔离测试环境。原生对照使用相同文件字节、参数顺序、环境、Docker 端点和 CLI 版本；在干净环境分别运行，避免前一次部署残留影响后一组结论。证据中的口令均为测试假值，正式秘密不进入报告。

### 7.2 实验步骤与判据

| 实验与关联 | 注入或执行步骤 | 通过判据与必须保留的证据 |
| --- | --- | --- |
| V01 认领与轮换，T01／T07 | 分别在 Manager 消费认领 token、替换长期凭据的提交之后丢弃响应；Agent 重启并读取先存候选 | 能用同一候选连接确认，节点与 ledger_id 只绑定一次；旧凭据轮换后不能执行；认领材料不能被异节点／异账本复用 |
| V02 保存与幂等，T03／T07 | 两用户从同一 ETag 保存；成功提交后丢响应并原键重发；同键改正文；新建 Stack 重复 POST | 第一份成功、第二份 412 且草稿仍在；成功重试只返回原 version_id；不同输入 409；新建只产生一个 Stack；数据库指针与密文完整 |
| V03 授权两种顺序，T05／T08 | 暂停授权事务：先提交撤权再批准；另一次先提交许可再撤权 | 前者不发许可；后者允许已发许可在窗口内被消费，界面只称取消请求；记录事务顺序、permit_id、Agent 开始事实与实际副作用，不能将后者误判为即时撤权失败 |
| V04 迟到和重复，T07／T08 | 保存旧 authorize_start，在超过 10 秒、换 session_id、Agent 已本地取消后分别投递；同连接重复投递 | 旧 nonce／过期／异连接均不触发新进程，重复只读账本；未知时占用仍在；同时验证持久化后启动前再次期限检查 |
| V05 崩溃矩阵，T08 | 在受理事务前后、prepare 发送前后、授权提交后发送前、START_COMMITTED 后 exec 前、exec 后结果保存前、结果保存后 ack 前终止进程 | 未提交事务无残留；已知结果重报；可能有副作用的状态核对而不重跑；保存三方证据：Manager 表、Agent 账本、Docker 资源与进程调用次数 |
| V06 原生和文件边界，T04／T17 | 用 F01—F03 先原生对照，再经 Agent；故意污染 Agent 服务环境；改变已物化文件 | 渲染语义和实际资源一致；环境污染无影响、文件漂移拒绝；不支持引用在调用 CLI 前拒绝；不构建、不注入网络／卷、不自动接管同名项目 |
| V07 取消与停服，T08／T17 | 在准备阶段、已发许可、进程已开始、Docker 响应丢失时取消；制造不响应 SIGTERM 的进程；重启 Agent | 只有可证明未开始时直接 canceled；其他保留结果／未知；候选 10 秒宽限后回收进程组；命令结束不自动证明回滚；残留进程不因 PID 重用被误接管 |
| V08 Web 状态，T02／T03／T05 | A 慢响应晚于 B；保存中继续编辑；保存冲突；提交响应丢失后刷新；读取正文后撤权 | 旧响应不覆盖、继续编辑不被清除、冲突保留草稿；刷新查询提交回执而不生成新意图；内存正文清除且长期存储没有环境秘密 |
| V09 加密与恢复，T16／T17 | 备份期间写配置；错 key_id／密文；旧 HMAC 键重试；从旧 Manager／Agent 备份恢复；磁盘满 | 完整备份可解密且外键一致；错钥拒绝；旧摘要可比较；恢复阻止旧凭据越权和未知任务重放；提交失败不启动进程、不删除证据腾空间 |
| V10 受限输出与预算，T05／T14／T17 | 原始输出含测试秘密并超 1 MiB；构造 128 文件及边界外输入、8 MiB 编码边界；慢连接与队列满 | 摘要和普通日志无原始秘密；仅获准接口返回输出；截断后仍排空进程管道；超限整体拒绝；单节点拥塞不使其他节点无限等待 |
| V11 结果与恢复完整性，T05／T08／T16 | 命令正常退出后使资源观察失败；恢复到一个已经完成且 ack 的新操作受理前的备份；撤掉 node.read 后返回404，随后到达旧成功响应 | 观察失败保持核对与占用、只补观察；scope=all 找到备份缺失历史并保存 recovery_cases；404 清正文并丢弃迟到成功响应，不能恢复旧权限视图 |

F02 的标记只存在于测试构建上下文；不执行构建来证明“没有构建”。为进程调用点设置记录钩子并检查实际 image／事件事实。V03—V05 至少用可控执行器证明状态机，再以真实 Compose 复测对应边界；前者不能替代后者。

### 7.3 记录与进入下一阶段

每项实验保留：运行版本、夹具摘要、故障点、消息顺序、数据库提交位置、实际资源变化、预期与实际差异及结论。日志脱敏后仍要能按 operation_id／permit_id／event_seq 交叉核对；不以 HTTP 202 或命令退出码单独作为成功依据。

M0 的输出应足以决定技术组合和协议是否可用：缺少迟到许可、账本损坏、文件环境或一致备份证据时，相关设计保持未验证；失败要改设计并重做相应用例。M1 验收再使用真实 Web 和 Agent 完成全流程。迁移 T09／T10／T15 和规模 T18 的完整断言仍按 O05／O08 分别推进，本节没有通过缩小 M1 将它们从产品目标删除。

## 8. v1 契约检查与新增故障用例
