# Docker Manager 测试与验收

日期：2026-11-02。版本：0.1。状态：待审阅。本文是测试计划及用例设计，尚无应用实现、测试部署或实际执行结果；文中的预期结果不代表已验证能力。

测试需要回答三类问题：用户能否完成管理任务；权限、配置和目标是否始终正确；中断、重试及恢复后能否说明发生了什么，并避免未经确认的重复副作用。验收按具体版本的交付范围进行，目标产品需求仍完整保留。

依据为[需求说明](requirements.md) v0.9、[功能设计](functional-design.md) v0.5、[架构设计](architecture.md) v0.3、[数据设计](data-design.md) v0.3 和[接口设计](api-design.md) v0.1。本稿将其中的规则转成测试输入、步骤和判断依据，不自行决定新的产品行为。传输协议、数值限额、兼容组合以及 Node Cross 的完整切换与回退尚未定稿，相关测试的前置条件在第八节明确。

## 一 范围与结果状态

测试覆盖 R01—R17、Q01—Q11，包含 Web、Manager、Agent、持久记录及真实 Docker／Compose 协作。PVE 与 Portainer 用于产品体验参照，验收以本项目需求和已采纳设计为准；不使用“看起来像某产品”作为通过条件。

Copy、Apply、Node Cross 分别验收。Copy 检查独立目标配置和来源不变；Apply 检查指定配置的目标部署；Node Cross 检查部署切换、迁移后验证以及验证通过后由用户选择是否删除来源。前两项通过不能代替迁移验收。

| 执行状态 | 使用条件 |
| --- | --- |
| 未执行 | 尚未运行本用例；本稿所有用例当前均为此状态 |
| 通过 | 指定版本和环境下完成所有必要变体，证据满足预期 |
| 失败 | 实际行为与预期不符，记录失败步骤、证据和缺陷 |
| 阻塞 | 本次已计划执行，但缺少环境、实现或设计前提，写明缺口和后续动作 |
| 不适用 | 在本次已明确的版本范围或环境中确实不适用，并有理由；不得用于掩盖失败或未实现 |

计划中的“待定稿”是就绪程度，不是执行结果。一个用例部分变体通过时不能把整项标为通过；记录各变体，并保留尚未执行或失败的部分。重试测试通过也不能删除首次失败记录。

## 二 验证层次与推进顺序

| 层次 | 目的与适合的方法 | 能证明的范围 |
| --- | --- | --- |
| 规则与模块 | 纯文本转换、路径校验、授权组合、状态转换、去重和版本比较的自动化测试 | 精确规则与边界，不代替真实节点执行 |
| 数据与接口集成 | 真实事务及文件存储、契约校验、并发屏障、消息重复和乱序 | 发布、持久化、鉴权与消息行为；模拟器结果单列 |
| 节点集成 | 实际 Agent、Compose、Docker Engine 和文件系统 | 路径、原生语义、执行与观察；记录实际运行组合 |
| 完整用户流程 | 浏览器与直接接口交叉验证，两个以上节点和不同权限账号 | 从入口到结果的可用性及后端权限，不只看按钮是否隐藏 |
| 故障与恢复 | 在明确阶段断网、终止进程、模拟写入失败及恢复旧备份 | 未知状态、证据保留、重复执行防护与恢复边界 |
| 规模与持续运行 | 固定负载、慢节点、输出压力和重复操作，采集资源曲线 | 指定负载下的性能与稳定性，不推导任意规模 |

建议先验证稳定工作目录与原生文件解析，再验证许可及崩溃窗口、持久记录和备份，随后贯通日常功能、权限和规模。它们对应架构第十一节的优先验证项；发现根本机制不成立时先修订设计，不用扩大用例数量代替解决问题。

开发者负责准备可重复的测试入口和诊断依据，测试执行者记录独立证据，用户审核产品行为及版本验收范围。可以由同一人或 AI 协作承担这些工作，不要求额外组织或审批层级。

每次修改只重跑受影响用例及其必要依赖；权限、任务执行、持久化和恢复等共同机制改变时扩大相应回归范围。对纯文档修订执行文档检查，不冒充软件回归。

## 三 环境与样例数据

### 环境记录

开始一轮执行前保存以下信息；缺项影响判断时记录阻塞，不用“默认环境”代替。

| 项目 | 必须记录的内容 |
| --- | --- |
| 软件身份 | Manager、Agent、Web 构建标识，数据结构及契约版本，启用能力和配置摘要 |
| 系统与执行组合 | Manager 与各 Agent 的 OS、文件系统、运行方式，Docker CLI、Compose、Engine 版本与实际 Engine 身份；CLI 所在位置和 daemon 所在位置分别记录 |
| 节点和网络 | 至少 A、B 两个独立 Docker 目标；Agent 主动连接地址、直连或代理路径、内外网关系、延迟及故障注入点 |
| 存储与路径 | 管理内容库、Agent 任务记录、稳定工作目录、测试卷、绑定路径、可用空间及文件权限 |
| 账号与授权 | 测试账号、系统管理资格、节点动作及凭据用途授权，授权变更前后版本 |
| 负载与限额 | 节点、Stack、容器、用户和订阅数量，文件／日志速率，配置的消息、缓冲、并发和超时限额 |
| 时序与证据 | Manager／Agent 时钟偏差、控制事件顺序的方法、日志与请求追踪、Docker 观察和数据快照位置 |

功能验证先使用两个真实且可清理的 Docker 目标。规模验证扩至约 20 个目标并覆盖内外网路径；模拟 Agent 可用于连接与消息负载，但不能据此宣布 20 节点的 Docker 部署及存储性能通过。

Linux、FreeBSD 等按实际可用 CLI／Compose 与目标 Engine 组合验证。测试记录必须说明运行位置、路径映射与已验证能力；某种客户端组合可用，不等于该平台具有同样的本地 daemon 能力。首先验证实际采用的组合，随后再扩大支持范围。

Manager 与受管节点的部署遵守架构中的主机信任边界。任意部署权限属于可信运维授权，不设计“同一宿主机上互不信任租户仍被管理界面强隔离”的通过标准。

### 公共测试数据

| 数据集 | 构成与用途 |
| --- | --- |
| D01 账号 | 系统管理员；A 节点观察者；A 的配置编辑者且无部署权；A、B 的运维用户；来源可读且目标可创建但不可部署的复制用户；没有 B 权限的用户。按用例增加精确授权，不用角色名代替动作清单 |
| D02 同名对象 | A、B 上同显示名但不同标识的 Stack／容器，另有目标同名未接管 Compose 项目及固定端口冲突 |
| D03 原始配置 | 单文件、多文件及顺序变体、profiles、include、包内 `../` 引用、`.env` 与 service env_file、注释和换行、附属文本及二进制文件、无效草稿 |
| D04 运行数据 | 可丢弃命名卷、匿名卷、绑定目录及外部卷／网络；写入已知标记与摘要。配置文件和业务文件分开，也准备混放冲突样例 |
| D05 镜像与仓库 | 已构建的可重复测试镜像及其摘要、错误引用、可控制的认证仓库和短期测试凭据；记录拉取策略，减少外部标签漂移干扰 |
| D06 秘密标记 | 分别标记管理器仓库密码、Agent 凭据、用户自行写入的配置秘密、应用日志秘密；使用可识别测试值，以区分不同保护规则 |
| D07 转换文本 | 普通 run、引号／转义／续行、环境和挂载、命名卷、自定义网络、未指定网络、`--rm`、未知选项、缺失 env 文件及 shell 表达式 |
| D08 恢复样本 | 一致备份、缺失内容文件、缺失密钥、受损清单、不同结构版本；备份之后另有新配置和 Agent 新任务记录 |
| D09 流量与边界 | 空／缺省／null 输入、边界长度、超限分片、重复和乱序事件、大日志、慢消费者、持久存储失败及受控时钟偏差 |

所有带删除、数据损坏或崩溃的步骤仅针对本轮专用测试目标。每例记录实际创建的原生对象和目录，清理按这份清单进行；不按通用名称猜测或递归清理共享路径。失败证据保存后再重置环境，不能让前例残留冒充本例输入。

## 四 核心功能用例

下列用例中的步骤按顺序执行；包含多个分支时分别记录。证据列说明最低观察面，不能仅凭界面提示判断后端或数据结果。方法名及错误语义来自接口设计，物理路径和脚本在实现阶段填入执行记录。

### 账号 节点与目标

| 编号 | 前提与操作 | 预期结果 | 证据 |
| --- | --- | --- | --- |
| T01 | 未初始化 Manager，用有效和无效引导材料尝试初始化；并发两次有效提交；初始化后再次提交。再用两个管理员并发停用／降权到可能无管理员的状态 | 无权初始化被拒绝，初始化只完成一次；不会留下零个可用管理员；失败不重新开放匿名初始化 | 用户、初始化和授权事务记录，认证响应 |
| T02 | 使用 D01，分别从 Web 和直接接口访问 B、配置正文、blob、操作输出、统计、日志、终端；替换 node／stack／resource 标识及分页游标 | 所有入口按当前对象和动作授权；不可见对象、计数、冲突引用及秘密不泄露；拒绝动作无未授权副作用 | 响应与流记录、审计、目标前后观察 |
| T03 | 打开编辑器和受限订阅后，分别退出、停用账号、撤销权限及令会话失效；再用旧作用域重发，重新登录查询原操作 | 受限访问关闭，旧作用域不产生新副作用；本地未提交内容可按功能设计保留，重新登录不自动重做变更 | 会话及授权版本、请求键记录、订阅关闭原因 |
| T04 | A、B 的 Agent 主动接入；尝试过期／已消费注册材料、响应丢失后重试、撤销身份、双连接、Engine 身份变化 | 注册不重复签发身份秘密；同节点仅一个当前执行连接；旧连接不能获新许可，身份变化先核对 | 身份、连接代次、任务许可及节点状态 |
| T05 | 打开 A 的编辑或动作窗口，切主页面到同名 B；提交原窗口。再令 A 离线并查看汇总和详情 | 动作仍固定原目标且提交前可识别；B 不被误操作；离线显示时间和不可用，其他节点可查询 | 请求目标、两端资源差异、页面记录 |
| T06 | 对已有工作负载节点执行解除管理；分别选择保留／删除管理配置；存在未知任务时尝试解除，再重新注册 | 旧凭据失效，Docker 工作负载与数据不被级联删除；未知任务须核对，重新关联不凭显示名 | 管理记录、凭据状态、Engine 前后观察 |
| T07 | 创建／调整／移除分组和标签；限制用户仅能访问 A，再查询列表、计数及过滤选项 | 分组与标签符合功能建议，删除分类不删除节点；不继承权限，统计不泄露 B | 分类关系、授权差异、列表与筛选响应 |

### 配置 原生行为与生命周期

| 编号 | 前提与操作 | 预期结果 | 证据 |
| --- | --- | --- | --- |
| T08 | Web 创建 D03，上传／下载并编辑；保存有效与无效草稿；尚未 Apply 时观察节点 | 原始字节、文件布局和顺序可解释；无效草稿标错且不能部署；保存不写运行目录或启动工作负载 | 下载字节摘要、revision、目录与 Docker 观察 |
| T09 | 两编辑者从同版本提交；丢弃胜出请求响应并同键重发；部署该版本时保存下一版 | 一次版本更新成功，另一方冲突；重发返回原版本，执行固定已提交输入，不换成新草稿 | 版本链、请求去重、ExecutionInput、实际调用输入 |
| T10 | 用相同 D03、环境和工具版本分别做原生 Compose 解析及管理器校验／部署；改变多文件顺序、include 目录、插值输入和 profiles | 支持范围内结果遵循原生语义，原文不被规范化覆盖；预览与执行使用相同来源，Manager 无关环境不混入 | 原始输入、解析差异、执行环境来源和实际资源 |
| T11 | 分别测试仅 build、有 image 和 build、缺失可用镜像、非启用 profile 中的构建配置 | 不触发构建；能按不构建策略使用镜像的输入依原生规则处理，否则明确拒绝；不删除 build 原文 | 原文、实际 CLI／Engine 调用、构建调用观察及资源变化 |
| T12 | Apply 后在绑定目录写 D04 标记，再改配置部署；测试单文件挂载、包内 `../`、越界文件条目、符号链接与外部修改 | revision 更新不迁走业务目录；受管理文件写入及部分失败如实记录；越界写入拒绝，外部漂移须明确处理 | 实际路径、标记摘要、落地清单、运行内看到的文件内容 |
| T13 | 成功部署旧版后保存未部署新稿，执行启动／停止／重启；另造部分部署失败后尝试控制 | 控制既有项目及已核对范围，不应用未部署草稿；失败与未知不冒充回滚，操作结果与当前健康分别显示 | 控制输入、配置版本、资源与健康观察 |
| T14 | 接入已有资源；分别提供完整／缺失配置；普通新建和 Copy 尝试占用未接管同名项目；执行显式接管 | 资源可见且配置缺口明确；不隐式覆盖或重建；接管保留经核对路径与归属，不自动部署 | 绑定、原目录、原有资源和配置前后摘要 |

### Copy 资源与诊断

| 编号 | 前提与操作 | 预期结果 | 证据 |
| --- | --- | --- | --- |
| T15 | Copy A 的固定 revision 到 B，重复提交；先不 Apply，再部署；修改或删除 A 的配置后读取 B；另测来源离线及目标冲突 | 一次提交只建一个独立目标；Copy 不部署，Apply 不改变来源；B 的内容不依赖 A 后续存在；外部依赖缺口可见 | 两端 revision／引用、内部复制及部署操作、资源差异 |
| T16 | 用来源可读、目标可创建但不可部署的账号执行 Copy／Apply；在复制提交前撤销来源权限，再在合法发布后撤销 | 可按权限保存独立目标但不能部署；提交前撤权阻止复制；合法目标按目标授权保留，凭据授权不随复制继承 | 两端授权与事务顺序、凭据引用、目标状态 |

| T18 | 分别解除配置、移除运行资源、删除容器／镜像／网络／卷及执行清理；包含仍被使用、关系未知、外部资源及 D04 数据 | 配置、运行资源和持久数据影响分开；删除数据须明确选择与授权，默认不递归删除绑定目录；实际使用冲突按原生结果报告 | 删除范围、权限、原生资源关系和数据标记 |
| T19 | 用 D06 执行拉取、轮换／撤销凭据、导出配置、查询错误／审计／缓存和上传／下载；尝试猜测 blob 及重复内容引用 | 管理器已知凭据不出现在普通输出，任务使用明确版本和用途；配置／应用日志秘密按对应读取权保护，物理去重不越权 | 脱敏日志与响应扫描、凭据版本、临时认证环境与清理记录 |

### 一致性 故障与管理恢复

| 编号 | 前提与操作 | 预期结果 | 证据 |
| --- | --- | --- | --- |
| T22 | 同键同输入／不同输入重发，返回丢失、查询与在途提交并发；换会话或恢复代次重发；清理详细结果后再用旧键 | 原作用域内只返回原受理结果；输入冲突拒绝；旧作用域失效，墓碑阻止键重新产生副作用；不能以查询暂未找到证明未执行 | 请求作用域、键与摘要、墓碑、Operation 和节点动作计数 |

| T26 | 旧部署未知，经证据核对安全释放后新部署成功；再补报旧成功，另测 binding 改变 | 旧结果仅补历史，不倒退最近成功引用、不解除新任务占用；核对不伪造原命令成功 | 部署序号、binding、占用所有者、核对与成功引用 |
| T27 | 上传完成与发布失败、多人保存冲突；Copy／下载／备份和内容回收并发；删除中文件再次被引用；模拟写入失败 | 不发布缺失或非就绪内容，活动引用／占用保护内容；失败可留下待回收孤立内容，不误删正式文件 | Blob 状态、引用／占用事务、文件字节及发布结果 |
| T28 | 保存并发时生成备份，在一致快照与固定文件引用之间中断，并让回收器运行；使用 D08 缺件／缺密钥变体 | 准备阶段回收屏障与内容占用有效；只有完整校验后标为可用；失败备份和缺失材料不伪装可恢复 | 快照、BackupManifest、占用／回收记录、包内容校验 |

T30 的模型级规则可先验证，网络编码与超时数值分支须等待物理契约。T32 的版本与安装步骤须等待实际发布物及运维方案，不能凭本稿编造可运行命令。

## 五 原生行为与转换的判断方法

### Compose 对照

T10 的对照必须固定 Compose 版本、原始文件、文件顺序、项目名、项目目录、profiles 和变量来源；分别记录 CLI 所在文件系统与 daemon 能看到的挂载路径。将管理器结果与相同输入的原生结果比较，允许排除已说明的非语义差异，例如资源生成时间和不透明 ID；不能排除实际路径、环境值、网络模式或卷身份差异。

至少逐项覆盖：

1. 两个 Compose 文件顺序互换时的覆盖结果；include 和普通多文件的不同路径基准；项目目录为文件包子目录时的包内 `../`。
2. 插值输入、`.env`、显式环境文件与 service env_file 的分别作用；同名变量取不同测试值，并在 Manager 进程设置无关同名变量，检查它未混入用户部署。
3. 选定与未选定 profiles、现有外部网络／卷、绑定文件与目录；缺失依赖不能显示为已满足。
4. 保存及下载原文的注释、换行、字符和二进制附属内容；解析输出不能成为唯一保存形式。
5. 实际工作目录不随 revision 改变；单文件挂载在更新后是否看到正确内容，应由容器内观察验证，不能只检查宿主机目标路径有新文件。

真实部署后的检查以运行配置、环境、挂载来源、网络和受控应用响应为依据。命令退出码、容器运行、健康检查和业务响应分别记录，不能互相替代。对于并非所有应用都有的健康检查，记录不适用原因，使用本用例预定的验证方式。

### run 转 Compose 样例

以下是 T21 必须保留的输入类别与判断依据；支持列表会随实现明确，但不能静默丢弃未知参数。所有内容先作为文本传给转换器；用于原生行为对照的固定样例由测试驱动在可丢弃环境另行执行，不把任意用户输入交给 shell。

| 样例 | 必须检查的结果 |
| --- | --- |
| `docker run -d --name web -p 8080:80 nginx:alpine` | 草稿保留镜像、容器名、端口和本稿功能设计要求的明确 bridge 模式；`-d` 的处理有说明；转换本身不创建容器 |
| 上例加 `--rm` | 自动删除语义未保留时必须提示差异，不能与普通输入得到相同的无提示“完成”结果 |
| 引号内空格、转义引号及反斜杠续行 | 参数边界与预期 argv 一致；不能按空格简单切割，无法确定边界时停止完整转换 |
| 含字面量 `$`、待展开变量或命令替换的输入 | 已确定的字面量在 Compose 中保持值；未解决展开需用户处理；不使用 Manager 环境或执行替换表达式 |
| 命名卷、自定义网络、绑定路径 | 实际名称和路径含义保留；按既定转换策略标出 external 依赖及“原生 run 可能创建、当前策略要求先存在”的差异 |
| `--env-file` 未提供文件或文件含 `VALUE=hello # world`、引号和 `$` | 缺文件保持待处理；取得文件后检查值不会因注释或插值规则而静默变化；采用 raw 等版本能力时有对应运行验证 |
| 未知选项、管道、重定向或多条命令 | 不执行；无法判断选项取值边界时不猜测镜像位置，不把不完整输出直接标为可部署 |

在受控环境布置一个测试标记文件和可观察的进程／网络出口，把含命令替换的文本交给转换器；检查没有额外执行或写标记。日志中不得保存整段含秘密命令；已映射、差异和阻塞项分别可见。转换后的 Compose 能解析，不足以证明与原命令行为一致；有已声明差异时按“差异正确披露”而非“完全等价”判断。

## 六 故障注入与竞争窗口

T23—T29 需要可控屏障或等效的阶段观察来安排事件次序。随机断网可以补充探索，不能代替证明故障发生在所声称的窗口。执行记录写明屏障名称、已持久状态、实际中断点和恢复动作。

| 窗口 | 注入位置 | 必须观察的结果 |
| --- | --- | --- |
| W01 | Manager 已持久受理与 outbox，尚未派发 | 重启后找回原操作及键；仍需时限、当前授权和节点条件，不产生新用户操作或无限期排队 |
| W02 | Agent 已持久准备，尚未获开始许可 | 不改运行目录或 Docker；取消必须取得未开始证据，重新连接不跳过许可 |
| W03 | Manager 已持久许可／running，许可交付或接受不明 | 不能从通道超时推断未执行或失败；先核对，旧连接许可不在新连接直接启动任务 |
| W04 | Agent 已持久接受许可，进程调用前后边界 | 重启不直接重跑；依据任务与执行者证据判断，可确定未开始时才重新协调，不确定保持未知 |
| W05 | 原生调用发生或完成，但可靠终态尚未持久保存 | 用独立副作用记录确认事实；不能因无结果记录就自动重复调用，也不能只看资源存在宣布整项成功 |
| W06 | Agent 已持久结果，Manager 尚未接收／提交 | 重传原结果及事件键；不重复执行任务，必要证据保留 |
| W07 | Manager 已提交结果，确认返回丢失 | Agent 可重复补报，Manager 返回原持久确认，不新增执行或倒退成功引用 |
| W08 | 受管理文件只更新一部分，或更新后尚未调用 Compose | 记录真实落地清单及部分副作用；已挂载配置可能生效，不能报告运行侧完全未变或自动回滚 |

每个适用窗口分别测试断连接、Manager 重启及 Agent 重启；无法适用的组合说明原因。写入失败分别发生在 Manager 元数据、内容文件和 Agent 任务记录，不能用一种磁盘错误代替所有路径。

**如何判断没有重复副作用：** 同时取得 Manager Operation、Agent 原任务键、执行者实例和原生调用观察。使用测试应用或测试执行器的独立计数标记帮助识别重复调用；不要仅以“最终只有一个同名容器”判断只执行了一次。对不可判定窗口允许结果未知，本计划不要求凭空证明跨数据库、进程与 Docker 的严格恰好一次执行。

**如何安排授权竞争：** 在许可事务提交前后分别暂停，以确定撤权或取消先发生的次序。授权先提交时，已批准范围可以继续，后续受限输出须关闭；撤权先提交时不得批准新开始。权限通知丢失也不能绕过提交时检查。

**如何验证冲突范围：** T37 使用同一个活动项目与其实际所属容器，分别从 Stack、容器和节点清理入口提交冲突动作，并交换先后次序。对范围无法可靠缩小的清理验证节点级排他；原任务失联或重启后仍检查占用存在。清理或删除没有执行不能只由错误响应推断，还需核对实际 Docker 调用及资源。其他节点的独立变更与查询作为同时进行的正向对照。

**如何验证预检不越权：** T38 在节点放置只属于测试的标记文件和专用凭据，分别观察 Manager 是否派发 Agent 检查、Agent 是否访问该文件及凭据是否被解密交付。structure 返回的“未验证依赖”不能通过后台补读悄悄消失；target 请求被拒绝时也不能先读后拒绝。完整解析输出另查配置读取权，不把部署权等同于预览读取权。计数与访问观察仅由测试设施取得，不要求生产日志记录秘密正文。

**如何安排迟到结果：** 人工核对先确实排除旧执行者，再解除旧占用，执行新部署并确认较高序号成功，最后补报旧结果。不能为了制造场景而省略隔离旧执行者的条件，也不能将人为填写成功当作原命令结果。

**如何验证备份与回收：** 在创建一致数据库视图之前建立备份准备屏障，暂停在快照取得与占用建立之间，同时尝试回收被快照引用的内容。重启后验证未完成准备不会仅因超时解除保护；既要检查备份能恢复，也要检查失败备份最终可明确终止并解除相应占用。

测试结束先保存证据，确认旧执行者不再可能运行，再按对象清单清理测试资源。恢复旧管理数据库前隔离旧 Manager，确保不会同时有两个有执行权的管理端。

## 七 规模与稳定性验证

T31 使用约 20 个独立 Docker 目标作为参考规模，节点数不是唯一负载指标。每轮先填写负载表，再确定测量时段及通过目标；当前不凭空承诺响应秒数、吞吐量或无限规模。

| 负载参数 | 必须预先记录 |
| --- | --- |
| 节点 | 真实与模拟数量分别列出，网络路径、慢／离线节点数量 |
| 资源 | 每节点 Stack、容器、镜像、网络、卷数量，以及配置文件数和大小 |
| 用户与操作 | 同时在线及活动用户、查询／编辑频率、并发部署数及动作比例 |
| 输出 | 日志生成速率、平均片段大小、订阅数、慢消费者比例 |
| 运行时段 | 预热、稳定采样、持续运行和恢复观察时段，参数调整点 |
| 资源预算 | Manager／Agent CPU、内存、磁盘与网络资源，队列和输出限额 |

至少区分四轮：日常混合负载；单节点慢或离线；大量日志与慢消费者；反复部署、重连、保存和清理的持续负载。第 21 个节点接入只验证没有 20 的硬编码上限，不代表 21 节点或更大规模已经满足性能目标。

采集请求延迟的中位数及高分位、错误与超时数量、操作受理到开始及完成时长、许可／结果确认延迟、控制与输出队列长度、数据库写入等待、内存和磁盘增长、重连次数、输出截断和关键记录缺失。区分成功、拒绝、失败和未知，不能只统计最快的成功请求。

通过条件分为两部分：

- 功能不变量始终满足：授权有效、固定目标与输入不变、关键结果不丢失、慢节点不使其他节点查询整体失败、输出受限且截断可见。
- 性能目标在该轮验收前明确并与负载一起记录，由实测基线和用户使用需要确定；未确定阈值时只能交付测量报告，不能写 Q09 性能验收通过。调整目标后保留版本和依据，不在看到结果后暗改标准使其通过。

持续运行检查稳定负载下资源是否持续无界增长，结合保留与回收周期解释预期增长；不得凭短时间内曲线平缓就宣布长期稳定。实际测试时长和增长容许范围须先写入执行计划。

## 八 前置缺口与分阶段覆盖

| 缺口 | 可先做的验证 | 不能提前宣布通过的内容 |
| --- | --- | --- |
| 应用尚未实现 | 文档追溯、示例与测试可执行性检查 | 全部软件功能、性能及恢复结果 |

开发实施计划可将已明确能力划入先交付版本，例如先交付 Copy／Apply；版本说明必须列清本次包含和未包含的需求。某项暂不交付时，其完整目标及测试缺口继续保留，不通过更名或标记“不适用”消失。

## 十 执行记录与缺陷处理

每轮执行先记录范围、构建和环境，再逐例保存实际步骤和结果。可使用 Markdown 表格或已有测试工具，不要求新建专用管理系统。建议执行记录放在后续建立的 `docs/test-results/`，本轮不创建空报告或虚构运行记录。

单条记录至少包含：

| 字段 | 说明 |
| --- | --- |
| 运行与用例 | 本轮标识、T 编号、具体数据及故障窗口／分支，不只记录大类 |
| 依据 | 需求和设计版本、预期结果，以及本轮是否纳入交付范围 |
| 环境 | 构建、实际系统与工具、配置、身份、负载和限额的清单引用 |
| 输入与步骤 | 原始测试样例、必要目标与版本、操作顺序、屏障和注入点；敏感原文受限保存 |
| 实际结果 | 响应、操作状态、资源与文件变化、观察时间；失败或未知如实记录 |
| 证据 | request／operation／task／event 标识、脱敏日志、原生观察、文件摘要及必要页面截图 |
| 判定 | 未执行／通过／失败／阻塞／不适用，执行者和时间，具体理由 |
| 后续 | 缺陷或缺口、修改版本、影响分析、重跑用例及原失败记录链接 |

故障证据用任务与事件作用域关联，时间戳只辅助阅读；跨节点时钟不同不能用时间先后代替许可、序号或事务依据。测试报告中的秘密要脱敏或限制访问，公开报告只保留可核对的引用。

失败先判断环境故障、设计矛盾或实现缺陷；尚无结论时写待核对。修复后重跑原失败输入和受影响分支，确认没有把失败条件删掉；必要时将新场景补入本计划。设计改变则先更新规则主出处，再更新用例，不能只修改预期让实现显得正确。

## 十一 版本验收条件

进入执行需要具备相应实现、可重置环境、固定输入、观察手段和判断依据；不要求所有后续功能都已完成才测试当前模块。进入版本验收前则必须明确本次声明的能力、实际兼容组合、参数限额与适用性能目标。

一个版本可提交用户验收的条件建议为：

1. 声明交付的需求均有实际执行记录；相关必要变体通过，失败、阻塞和不适用有可见清单，不能用总体通过率掩盖关键失败。
2. 无尚未解决的越权访问、错误节点执行、未选择的数据删除、关键记录／内容丢失或可能造成重复副作用的执行缺陷。发现这类问题时停止相关能力的验收，保留证据并修复。
3. 对已声明支持的节点与工具组合，关键用户流程、原生文件行为、断线恢复、备份恢复和受影响的回归已验证；测试范围与支持声明一致。
4. 性能结果对应已记录负载和事先确定的阈值；没有阈值或没有真实节点证据时，仅提交测量和局限，不能宣布相应规模验收完成。
5. Node Cross 若列入交付，必须完成真实切换与验证、来源保留／删除选择及适用失败恢复用例；只完成 Copy／Apply 或迁移模型测试时明确不作这一声明。自动搬运数据按单独确定的支持范围验收。
6. 用户能够从报告中判断本次可用功能、已验证条件和剩余缺口，并审阅实际流程；用户审阅认可不替代软件测试证据，软件用例通过也不替代产品体验审阅。

低影响的已知问题可以连同影响和处理安排提交用户判断，不预设必须零缺陷或固定百分比。验收结论限定到本次构建、范围和环境，后续改变依影响选择回归。
