# Docker Manager 开发实施计划

日期：2026-11-02。版本：0.1。状态：待审阅。阶段顺序和任务划分为实施建议；当前尚未开始应用开发或执行技术验证。

本计划把已经形成的需求、设计、测试和运维约定组织成可交付的开发工作。推进主线是：先验证执行环境和故障处理基础，再完成账号与节点接入、Web 配置和 Compose 部署，逐步补齐日常管理与运维交付，最后按单独设计和验收条件交付 Node Cross。自动搬运存储继续保留为目标，按用户要求暂缓展开。

本计划面向用户、开发者和测试执行者，说明每项工作要交付什么、依赖什么、依据哪份设计，以及如何判断完成。它处于项目实施安排的层次；具体代码目录、函数、构建命令和逐步施工单在技术组合与物理契约确定后，随相应任务补齐，不在此虚构尚不存在的项目结构。

### 贯穿开发的约束

- 节点管理与迁移体验参考 PVE，节点内 Docker 操作参考 Portainer；具体交付范围以需求条目为准。
- 多人是可信运维协作，按节点和动作授权；任意部署能力不被包装成同主机不可信租户隔离。
- Agent 主动连接 Manager，覆盖内外网混合环境；不要求节点间直连，不设置 20 节点硬上限。
- Web 可以创建、保存并部署原生 Compose；配置版本、已执行输入和当前运行状态分别表达，保存不部署。
- 使用 Unix-like 环境下的 Docker CLI、Compose 和 Engine；支持声明限定到实际验证的组合，不把 FreeBSD 名称直接等同于原生 Docker daemon 能力。
- 不提供 Build、Dockerfile 和构建上下文管理。保留用户原文，遇到必须构建才能满足的依赖明确报告；不得通过删字段改变含义。
- Copy 保留来源并创建独立目标配置，Apply 是明确目标部署；Node Cross 要完成部署角色切换、迁移后验证，再由用户选择来源保留或删除。
- 来源配置、运行资源和持久数据的删除分别说明范围与权限。验证失败、未知或失效时不得清理来源。
- 自动化存储搬运暂缓；前期可以手动准备数据，但不把准备声明、Copy 或 Apply 成功报告为迁移已经验证完成。

Go、Vue 3／TypeScript、SQLite、一个活动 Manager、WSS 及节点原生服务等仍是既有设计中的候选。P01 会形成可比较的选择依据与具体方案；本计划没有把这些候选改成已确认技术栈。

## 三 开发任务与完成条件

所有任务当前均为未开始，P18 为明确暂缓。任务中的测试编号引用[测试与验收](test-plan.md)，运维编号引用[部署与运维](operations.md)。每项完成都需要成果和相应检查证据；文档已写、原型能跑或页面存在，均不能单独将实现任务标为完成。

### P01 确定开发与验证基线

**依赖：** 无，先以现有项目资料开始。

读取需求约束、架构候选和可用资源，形成语言／前端、存储、部署形态、Docker 访问方式和传输候选的选择记录。比较实际 Unix-like 运行条件、依赖维护、构建发布、事务及任务恢复需要；需要用户裁定的技术选择集中给出理由和代价。与此同时，核对哪些用户和节点可用于隔离验证，明确开发者、验证执行者与用户的职责。

**交付与检查：** 可复现的开发环境说明、候选选择及状态、代码与测试职责目录方案、首批验证环境清单、样例数据及清理办法。清单至少为两个独立 Docker 目标、所用 CLI／Compose／Engine、路径视图和网络条件留下明确记录；未取得的环境标明影响，不假设可用。源代码与依赖管理、构建和测试工具在此落定，后续任务才填写真实文件路径与命令。

**设计出处：** 需求第一至四节与第九节；架构第一至四节；测试第三节；运维第一至三节。完成表示能够开展下一项验证，不表示全部候选机制已被证明可用。

### P02 验证路径 原生行为与关键故障窗口

**依赖：** P01 的首批环境和原型工具选择可用。

在可重置目标上做小范围技术验证：稳定工作目录、多文件与 include、相对路径、单文件绑定挂载和远端 Engine 路径；原生 Compose 的不构建执行；许可、进程调用和结果持久化边界的重启；撤权与取消竞争；慢日志与控制通道隔离。原型使用测试身份和固定样例，不承担正式账号或通用管理入口。

**交付与检查：** 每个验证有环境、操作、预期、实际证据、失败假设和设计影响。重点采用 T10—T12、T23—T25、T30 的相关分支及故障窗口；模拟结果明确标注，不能替代真实 Docker 和进程故障证据。验证失败先修正执行路径或协调机制，再让受影响任务进入实现；原型代码后续复用须进入正式实现与测试。

**设计出处：** 架构第五至八节及第十一节；数据第四、五、八节；接口第六至八节。P02 解决关键可行性问题，正式实现仍在 P07、P08 复验同类窗口。

### P03 定稿可实现的契约与初始限额

**依赖：** P01；纳入 P02 对输入、持久化和传输的验证结论。

将逻辑接口转换成选定传输下的路径或消息、认证载体、字段类型、错误、版本协商、超时和资源限额。固定请求作用域、任务键、事件流、摘要编码与共享测试向量；统一名称、单位、缺省／null、序号精度、上传和流帧规则。按当前实现批次展开动作 schema，尚未实现动作不得通过通用调用入口提前开放。

同时将首批实现涉及的数据模型落成所选存储的结构、唯一性与引用约束、事务边界和结构版本迁移规则。后续配置、任务及备份模块扩展结构时沿用同一方式，不由各模块临时决定身份、序号和保留语义。

**交付与检查：** 首批机器可读契约、存储结构及约束校验、示例和跨端校验，确定的参数名、默认值及允许范围，Manager／Agent 初始兼容规则。T30 的字段、编码和越界部分应可执行；错误输入不能静默丢弃行为字段。后续任务增加动作时同时更新契约、存储结构与相应限额，不要求这里提前冻结所有扩展。

**设计出处：** 接口第二、四、六、八、十三节；数据第二、八、十节；运维第十二节。Node Cross 完整执行接口等待 P16，不在此以通用占位字段替代。

### P04 完成初始化 账号与授权基础

**依赖：** P01、P03。

实现受控初始化、登录退出、账号维护、最后管理员保护、节点动作授权与会话作用域；建立可复用的授权查询、请求去重和审计基础。Web 与直接请求采用同一规则，权限变化影响后续请求和受限订阅。密码、会话及 Agent 凭据的保存和生命周期按已确定技术方案实现。

**交付与检查：** 可登录的开发版本及账号、授权和审计存储；T01—T03、T19、T22 的身份与请求分支通过，O01 有开发环境中的实际入口。节点执行和任务开始的竞争验证在 P07 补齐，不能以登录页完成代替权限完成。

**设计出处：** 功能第二节；数据第三、七、八节；接口第二至四节；运维 O01、O04。

### P05 完成 Agent 接入与节点观察

**依赖：** P02、P03、P04。

实现一次性注册、认证回连、单个当前执行连接、身份撤销与替换、Engine 身份核对、能力和新鲜度观察。接入至少两个独立目标，展示已有资源和可识别项目及配置缺口，提供节点列表、详情、分组标签、授权筛选和部分失败反馈。连接与任务身份分别保存，为 P07 提供明确上下文。

**交付与检查：** M1 节点查看流程；T04—T07、T14 的只读发现部分以及 T30 的连接兼容分支通过；O02、O04、O09 的接入和解除行为有记录。注册响应丢失不泄露身份材料，解除管理不删除应用，节点切换不改变已经打开的操作目标。已有任务的解除前核对由 P07 接入。

**设计出处：** 功能第三、七节；架构第三、四节；数据第三、六节；接口第一、五、八节。

### P06 完成配置版本 文件与凭据引用

**依赖：** P02、P03、P04；接入 Web 节点流程时使用 P05。

实现 Stack 草稿和不可变 revision、文件上传下载、完整清单发布、多人版本冲突、原始字节保留、有序部署输入及内容引用保护。建立秘密值版本与用途授权，提供后续任务可使用的引用，普通查询不返回密码。Web 支持创建、重开、编辑和导入，区分未保存、已保存与已部署；结构检查只处理已提供文件。

**交付与检查：** 从 Web 保存多文件配置并重新取得同一内容；T08—T10 的保存部分、T19、T22、T27 的内容发布与回收部分通过。保存不改节点运行目录，无效草稿有错误提示且不能被当成可部署输入。目标原生预检在 P08 完成，不能用结构检查宣称目标就绪。

**设计出处：** 功能第四节；架构第五节；数据第四、七、八节；接口第六节。内容回收须支持活动引用和占用；备份的持久保护在 P13 接入同一机制。

### P07 完成持久任务与故障核对

**依赖：** P02—P06。

实现 Manager Operation、固定 ExecutionInput、层级冲突占用、开始许可事务和 Agent 持久任务、执行者记录、事件补报及持久确认。统一所有将来产生节点副作用的调用入口。完成取消、未知结果、人工核对及安全解除占用；核对同时检查恢复管理和相应节点权限、证据归属与新鲜度。

**交付与检查：** 先用受控动作证明 T22—T26、T37 的协调机制，再用真实 Docker 副作用复验进程窗口。许可与撤权／取消有明确持久顺序；重连与重启保留原任务键，unknown 占用不因超时解除，迟到结果不倒退部署序号。O03、O08 有实际恢复路径。后续资源功能必须接入这套机制，不能另开简单命令通道。

**设计出处：** 架构第六至八节；数据第五、八、九节；接口第四、七、八节；测试第六节。

### P08 完成 Compose Apply 与生命周期

**依赖：** P05—P07，以及 P03 中对应动作契约。

贯通 Web 选定版本、目标预检、固定输入、文件暂存、授权开始、稳定目录落地、原生 Compose 调用及结果呈现。实现更新、重部署、启动停止、移除运行资源与删除管理配置的明确区别，清楚展示数据影响。新建部署先检查节点上的同名未接管项目，无法核实身份时阻止部署；不能等 P11 的接管界面完成后才增加这项保护。

**交付与检查：** M2 的创建到部署全过程可走查，T08—T13、T18、T23—T26、T38 的适用部分通过。预检绑定目标、输入摘要、版本、工具和时间，变化后失效；无部署或凭据用途权时不读取节点内容。已有新草稿不能被普通启动／停止操作隐式应用；原生构建调用必须为零。

**设计出处：** 功能第四、五节；架构第五、六节；数据第四、五节；接口第六至八节；运维 O02、O03、O08。

### P09 完成容器操作 诊断与交互流

**依赖：** P03—P05、P07；Stack 关联与跨入口控制使用 P08。

实现容器列表详情、独立创建及生命周期、所属 Stack 关系、日志、统计、操作输出和容器终端。每个入口固定目标与动作，订阅权限、终端输入和输出预算统一处理。容器直接操作不会自动回写 Compose 配置，关闭终端不声称已停止其中进程。

**交付与检查：** T02、T05、T17—T20、T30、T37 的相应部分通过；撤权关闭输出，断线不重放输入，同名替换容器不会被误操作，慢输出不阻塞控制或结果持久化。操作日志可追查，秘密及未授权关联不泄露。

**设计出处：** 功能第七、九节；架构第八节；接口第三、七、十节；运维 O03、O08。

### P10 完成镜像 网络 卷与仓库访问

**依赖：** P03—P07；与 Stack 的资源关联使用 P08。

实现镜像及标签、拉取、使用关系、删除和清理；仓库访问配置使用已授权秘密版本。实现网络和卷的查看、创建、删除及允许的清理入口，展示实际对象与持久数据影响。危险选项、清理筛选和卷删除明确传入范围，与项目和节点占用协调。

**交付与检查：** T17—T19、T30、T37 的资源分支通过，包括认证仓库访问、失败反馈、关联未知和正在使用的资源。删除不由缓存判定绝对安全，默认选项不扩大数据范围；不扩展为镜像构建、仓库托管或卷文件编辑功能。

**设计出处：** 需求 R09、R10；功能第七节；接口第三、五节；数据第六、七节；运维 O04、O09。

### P11 完成已有项目接管与独立 Copy

**依赖：** P05—P08；跨入口保护使用 P07 的共同机制，随后与 P09、P10 联合回归。

## 四 依赖安排与实施节奏

优先串起 P01 → P02 → P03 → P04 → P05 → P06 → P07 → P08，使真实节点的部署链路成立，再扩大动作类型。P06 的配置存储和编辑可以与 P05 部分交错；P12 的文本转换可以在账号、编辑与契约基础形成后独立推进；P09—P11 和 P13 在 P07、P08 稳定后可按人员情况并行。这里的并行是代码职责分工，不要求引入多个服务或并行 AI 代理。

共享的 task_key、ExecutionInput、权限目录、事件确认、冲突范围、秘密版本和数据事务必须先有一致定义。更改共同机制时，先更新主出处与共享契约，再同步消费它的任务；不能让各功能自行实现一份去重、授权或终态规则。

每项开始前形成简短施工记录，填写：

| 项目 | 应填写的具体内容 |
| --- | --- |
| 任务与范围 | 本计划任务编号、本次实际交付的动作及暂不交付部分 |
| 输入 | 需求、设计与契约版本，已完成的前置成果 |

| 验证 | 适用 T 用例及变体、测试入口、环境、真实运行命令和预期结果 |
| 数据与回退 | 需要改变的持久结构、运行资源及恢复办法 |
| 完成证据 | 构建标识、变更记录、测试结果、演示与必要文档更新 |

先实现该任务所需的验证入口和核心断言，再实现行为并运行检查。对原生 Docker、进程崩溃、网络断线和文件路径的判断需要真实环境证据；测试替身适合控制竞争次序，不能代替这些外部行为。低影响的文档或显示文字修改按影响检查，不机械增加软件测试。

推进记录使用未开始、进行中、待外部条件、待审阅和完成。缺少环境或产品决定时指出具体阻塞的任务，继续不依赖它的工作；完成要有实际证据，不能以百分比平均掩盖尚未通过的关键行为。阶段退出时再汇总本阶段范围及缺口，避免每个小修改都要求用户重新审批。

## 八 每次交付与文档收尾

任务交付至少包含可定位的实现或设计成果、依赖版本、适用测试结果、已知问题及受影响正文更新。涉及接口时，正文、机器可读 schema、样例和共享测试同步；涉及数据时，结构版本与恢复办法同步；涉及安装或维护时，实际入口与运维流程同步。

候选版本由 P15 汇总以下材料：

1. 明确构建标识的 Manager／Agent 产物、校验信息、来源与依赖说明。
2. 实际支持的系统、工具和 Manager／Agent 兼容组合，以及配置键、默认值、单位和限额。
3. 本次交付需求、实际测试证据、性能负载与阈值、已知问题和未交付事项。
4. 可按发布物执行的安装、节点接入、更新、备份恢复、排障与卸载说明。
5. 用户可审阅的典型操作演示，以及需要产品判断的剩余问题。

版本通过条件沿用[测试与验收第十一节](test-plan.md)，不新增形式审批。用户审阅不替代软件测试，测试通过也不能代替业务迁移验证。若某项证据缺失，缩小的是本次能力声明，不得悄悄删除完整需求。

当前八份主文档可以形成一轮完整初稿，随后仍有以下实质收尾工作：P01—P03 落实技术组合、物理数据结构和接口契约；P16 补全迁移切换与回退；P14 把运维流程补成真实入口；各实现任务和 P15 取得测试结果。自动存储搬运继续在 P18 暂缓。初稿齐备只表示资料已组织成可继续工作的依据，不表示这些问题已经解决。
