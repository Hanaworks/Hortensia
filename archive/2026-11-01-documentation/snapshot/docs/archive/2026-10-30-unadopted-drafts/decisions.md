# Docker Manager 设计决策记录

日期：2026-10-30。本文区分已经明确的产品方向与本轮设计提出的方案。方案写入文档不等于已经获用户确认；状态变更时记录日期、理由和影响文件。

## 已明确的产品方向

| 编号 | 结论 | 来源和影响 |
| --- | --- | --- |
| C01 | 自托管，多台独立节点，由用户选择部署位置 | 原始讨论及需求 R01、R02；不引入自动集群调度或独立 Service 层 |
| C02 | 主体参考 Portainer，Web 内编辑和部署 Compose，遵循原生行为 | 需求 R03—R05；不要求手动 SSH 维护配置，不擅自注入资源 |
| C03 | Node Cross 是核心方向，运行数据迁移可选 | 需求 R06、R07；配置跨节点部署无需等待数据迁移功能 |
| C04 | UI 随功能逐步细化 | 需求 R08；不以完整视觉稿作为设计文档或开发的前置条件 |
| C05 | 第一阶段个人自用，兼顾以后分享；节点处于混合网络 | 2026-10-30 用户答复，需求 R09、R10 |
| C06 | 账号设计考虑简单内置账号与 OIDC，也可直接 OIDC | 2026-10-30 用户提出；需要比较方案，尚未选择最终模式 |
| C07 | 现在开始编写需求、功能、架构等实际文档 | 2026-10-30 用户澄清；准备计划用作检查清单，文档可先形成相互衔接的初稿 |

## 本轮推荐方案

以下状态均为“提议”。此处记录设计理由；详细规则由对应设计文档维护，避免复制多套规范。

| 编号 | 推荐方案 | 比较过的替代方式 | 理由与代价 | 主要影响 |
| --- | --- | --- | --- | --- |
| D01 | Manager 加节点 Agent，Agent 主动连接 Manager | 管理端通过 SSH 操作节点；管理端主动连接 Agent | 适配部分节点无法被直接连接的混合网络；需要维护 Agent 和可被节点访问的 Manager 地址 | 架构、安装、节点注册与恢复 |
| D02 | 管理端保存配置权威版本，节点持有执行副本和稳定工作目录 | 节点文件作为权威，编辑时读取和同步 | 便于离线编辑和跨节点复制；需要备份管理器、识别节点副本偏离，不能把运行数据混入配置同步 | 配置模型、备份、外部修改规则 |
| D03 | 内置账号加可选 OIDC，并允许关闭本地登录形成 OIDC-only 模式 | 只实现内置账号；只实现 OIDC | 兼顾独立安装与已有身份服务；增加登录与恢复测试成本。实际首版登录模式仍由用户选择 | 登录、首次管理员、账号关联与恢复 |
| D04 | Node Cross 复制指定版本到独立草稿，不自动部署或删除来源 | 一键复制并部署；迁移后自动清理来源；两端配置联动 | 行为容易核对且便于调整目标差异；需要用户单独确认部署，后续再考虑快捷入口 | 功能、接口、验收 |
| D05 | 首版支持主 Compose、环境配置和文本附件，复杂构建与多文件组合后置 | 第一版就支持全部 Compose 输入来源与构建方式 | 控制文件传输和路径语义范围；若现有 Stack 大量依赖这些能力，需要调整首版范围 | 配置包、能力校验、兼容性 |
| D06 | 单管理端实例，Go 服务与 Agent、Vue 3 加 TypeScript、SQLite 与配置目录作为候选推荐组合 | TypeScript 全栈；其他前端；独立数据库 | 作为轻量自托管方案的起点；仍需核对开发偏好、依赖、备份一致性和实际负载，版本未选定 | 架构、开发环境、升级与恢复 |
| D07 | 外部 Compose 项目先发现与只读展示，配置接管后置 | 扫描文件后导入接管；根据容器反推配置 | 避免缺少原始材料时错误覆盖外部项目；已有容器的明确启停操作可独立支持 | 归属展示、功能范围 |
| D08 | 首版获准账号统一管理员权限，细粒度权限后置 | 预设管理员与只读角色；资源级 RBAC | 符合个人使用起点且减少权限矩阵；不适合直接开放给不可信协作者 | 登录准入、接口鉴权、分享使用边界 |
| D09 | 保存与部署分离，固定版本执行，未知结果先核对 | 保存即部署；断线后自动重试；自动回滚 | 降低重复执行和配置错位风险；需要持久任务记录和明确的未知状态 | 数据、执行协议、失败处理 |

## 本轮尚未获得的运行信息

- 初期节点、Stack 数量及增长预期，允许的管理器资源占用。
- 节点操作系统、CPU 架构、Docker 与 Compose 版本、是否使用 rootless Docker。
- Manager 所在位置，哪些节点只能主动连接，以及现有代理、VPN 和 HTTPS 条件。
- 现有 Compose 是否使用构建上下文、多文件合并、include、特殊设备和大量附属文件。
- 已使用或偏好的 OIDC 提供方，以及是否允许本地恢复管理员入口。
- 前后端语言偏好、现有运维方式和安装交付偏好。

这些信息用于修订设计和安排技术验证，不阻止先写成可审阅初稿。设计中不能把“尚未知道”写成“已经验证支持”。
