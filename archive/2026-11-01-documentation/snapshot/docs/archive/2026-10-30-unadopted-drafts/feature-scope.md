# Docker Manager 首版需求与功能范围

日期：2026-10-30。版本：0.1。状态：设计初稿。

本项目服务于管理多台独立 Docker 主机的个人使用者。用户在网页中维护 Compose，明确指定部署节点，并将已有配置方便地用于另一节点。第一版的成功标准是完成日常管理和跨节点配置复用，且配置行为容易理解、操作结果可以追踪。

[需求基线](requirements.md) 中的 R01—R10 是已明确方向。本文的首版取舍、操作细节和支持边界是本次提出的推荐方案，供审阅；不代表用户已确认完整范围，也不是对某一 Portainer 版本功能的逐项复刻承诺。

## 使用场景

| 场景 | 用户希望完成的事情 | 成功表现 |
| --- | --- | --- |
| 日常管理 | 查看不同节点及其 Stack、容器和运行情况 | 始终知道资源属于哪台节点，切换节点不会误操作 |
| 新建部署 | 直接输入 Compose 与环境配置，在指定节点部署 | 无需先 SSH 创建配置文件，能查看执行结果和日志 |
| 配置更新 | 修改已有 Stack，保存后选择何时部署 | 可以区分当前草稿、执行中的版本与最近成功部署的版本 |
| 配置复用 | 将节点 A 上的配置带到节点 B | 可以检查并调整目标配置，来源保持不变，运行数据边界清楚 |
| 故障判断 | 部署失败或节点失联后继续查看 | 不把未知结果伪装为成功或失败，不重复发起可能已执行的任务 |
| 登录使用 | 自己登录管理，必要时接入现有身份服务 | 首次初始化和恢复访问可完成，外部身份不会自动获得管理权 |

## 首版范围建议

“首版核心”优先形成可用流程；“首版补齐”在核心稳定后加入同一版；“后续”保留为候选。该顺序用于安排设计和实现，不是已承诺的工期。

| 编号 | 功能 | 对照方向 | 范围建议 | 具体边界 |
| --- | --- | --- | --- | --- |
| F01 | 登录与账号 | 基础能力 | 首版核心 | 简单本地账号及可选 OIDC；可配置仅 OIDC；最终登录模式待确认 |
| F02 | 节点接入与状态 | 沿用并调整 | 首版核心 | 注册、命名、在线与离线、能力信息、凭据撤销和移除管理关系 |
| F03 | 节点导航与总览 | 调整 | 首版核心 | 总览与节点上下文切换，操作展示目标节点；先不做完整跨节点搜索 |
| F04 | Stack 配置编辑 | 沿用并调整 | 首版核心 | 创建、查看、编辑 Compose、环境配置与受支持的文本附件；保存不自动部署 |
| F05 | Stack 执行 | 基础能力 | 首版核心 | 校验、部署、更新、停止、恢复启动和查看执行结果；固定本次执行的配置版本 |
| F06 | Node Cross | 新增重点 | 首版核心 | 复制配置到目标草稿，允许调整后单独部署；不自动删除来源或搬运运行数据 |
| F07 | 部署任务与日志 | 基础能力 | 首版核心 | 进度、退出结果、操作记录、断线后核对，不等同于持续监控平台 |
| F08 | 容器查看与基础操作 | 基础能力 | 首版补齐 | 列表、详情、状态、日志、启动、停止和重启；由 Compose 管理的容器提示操作影响 |
| F09 | 镜像管理 | 基础能力 | 首版补齐 | 列表、拉取、删除未占用镜像；不做自动批量清理或自动更新策略 |
| F10 | 网络与卷查看 | 基础能力 | 首版补齐 | 列表、详情和关联关系；手动创建、连接、删除等修改操作留待确认 |
| F11 | 已有资源发现 | 基础能力 | 首版核心 | 展示节点已有资源及可识别的外部 Compose 项目，标注管理归属 |
| F12 | 配置导出与管理器备份 | 基础能力 | 首版补齐 | 可导出管理配置并恢复管理器；敏感内容明确选择，不包含应用运行数据 |
| F13 | 交互终端 | 候选增强 | 后续 | 容器终端、会话恢复及权限细节单独设计；如为日常必需可提升优先级 |
| F14 | 接管外部 Stack | 候选增强 | 后续 | 首版不从运行容器反向拼出并覆盖原始 Compose |
| F15 | 全局搜索与批量操作 | 候选增强 | 后续 | 跨节点搜索、批量变更与自动更新不影响首版核心流程 |
| F16 | 历史浏览与回滚界面 | 候选增强 | 后续 | 首版保留部署依据用于核对；完整版本管理及一键回滚另行设计 |
| F17 | 运行数据迁移与移动 | 可选增强 | 后续 | 卷、数据库、bind 数据迁移及来源清理独立于配置复制 |
| F18 | 细粒度权限与团队能力 | 可选增强 | 后续 | 首版建议获准账号均有管理员权限；不开放公共注册，不承诺租户隔离 |

F11 的外部项目配置只读，不允许通过 Stack 编辑或部署接口修改；F08 对已有容器的启动、停止、重启属于明确的资源操作，不能据此声称接管了其 Compose 配置。停止外部容器也需要明确目标和影响。

## Stack 配置边界建议

一个受管理 Stack 绑定一台节点和一个稳定的 Compose 项目名，包含一组可编辑配置及部署记录。跨节点复制创建新的 Stack，不让一个 Stack 同时代表两台机器上的运行实例。

| 内容 | 建议首版行为 | 跨节点行为 |
| --- | --- | --- |
| Compose 主文件 | 保存原文，执行前由目标环境校验；不静默添加或删除配置字段 | 复制所选版本，可在目标修改 |
| 环境变量与 `.env`、`env_file` | 区分 Compose 插值输入与容器环境输入，保留文件和变量的用途 | 列出需要带走的值；敏感项必须明确选择或在目标重新填写 |
| 文本附件 | 管理配置文件和受支持的相对文件引用，保留包内相对路径 | 明确列入复制清单；含密附件按敏感项处理 |
| 绝对 bind 路径 | 是节点上的外部依赖，保存声明并提示目标检查 | 只复制路径声明，不复制路径中的数据 |
| 相对路径中的运行数据 | 存在节点固定工作目录下，配置更新不能切换为新的空数据目录 | 不随配置复制；目标检查是否需要初始化或提前准备 |
| 外部网络、卷、设备与宿主能力 | 保留原生声明，要求目标满足依赖 | 展示依赖，不擅自创建替代资源或改变声明 |
| 管理器保存的镜像仓库凭据 | 独立于配置包管理，按目标授权使用 | 不隐式复制授权；由用户为目标选择可用凭据 |
| 本地构建上下文、复杂多文件组合、远程 include | 首版建议暂不支持管理；遇到相关输入明确说明限制 | 不丢弃相关字段后继续部署 |

上述支持边界是管理器首版输入范围，不改变 Compose 自身的含义。无法识别或验证的功能应显示具体原因；校验通过也不保证端口、设备或外部服务在实际执行时仍可用。

敏感值可能直接写在 Compose 或附件中，不能仅检查管理器的凭据表。跨节点确认页应完整展示文件清单，并允许用户标记敏感文件；无法可靠自动识别的内容仍需用户审阅。

## 关键行为建议

1. 保存配置生成版本；部署引用固定版本。部署期间继续编辑不改变已发出的任务。
2. 节点离线仍能查看管理器中的配置并保存草稿，新执行请求明确拒绝，避免恢复连接后意外执行旧请求。
3. 同一节点上的 Compose 项目名不能与已知受管理或外部项目冲突；执行前再次检查，不能只检查管理器数据库。
4. Node Cross 必须指定来源版本，默认生成独立目标草稿、保留来源、拒绝同名覆盖；创建草稿与执行部署是两个动作。
5. 一个 Stack 同时只允许一个改变运行资源的任务。结果未知时先核对，不自动再次部署或删除。
6. 任务执行结果与容器运行健康分别展示；命令结束不意味着应用永远健康。
7. 移除管理记录与卸载部署分开。普通卸载默认保留卷，不删除 bind 数据；不隐含清理镜像、全节点资源或来源节点。
8. 首版不承诺执行中强制取消或自动回滚。关闭页面不会终止节点上的任务；失败后的残留资源和后续操作明确展示。

## 首个完整流程与验收

推荐先完成 F01—F05、F07、F11 的最小闭环，再加入 F06，随后补齐资源操作和备份。登录方式可先实现选定的基础模式，另一模式在首版补齐；不因此从整体设计中删除 OIDC。

| 场景 | 可观察的完成标准 |
| --- | --- |
| 新建部署 | 登录后接入一台测试节点，在 UI 输入有效 Compose，保存与部署分开；执行记录能定位节点、版本、开始与结束状态 |
| 更新部署 | 修改草稿不改变当前运行配置；部署后能对应到本次版本；失败时保留之前成功部署的记录和本次失败详情 |
| Node Cross | A 的指定配置版本可生成 B 的草稿；确认清单及目标差异后部署；A 的配置和运行资源不受影响 |
| 数据边界 | A 的卷或 bind 数据不会被复制；B 缺少必要依赖时给出具体提示，不能伪称完成数据迁移 |
| 断线恢复 | 执行期间连接中断显示结果未知；重连后根据执行记录核对，不把连接重试变成第二次执行 |
| 登录边界 | 没有有效登录无法调用管理接口；OIDC 身份未经允许不能创建管理员；身份服务故障不自动开放访问 |

详细流程见 [功能设计](functional-design.md)，技术方案见 [架构设计](architecture.md)，逐项验收见 [验证与交付](validation-and-delivery.md)。

## 需要用户校正的范围

优先校正三类内容：日常是否必须使用终端或手动管理网络与卷；是否必须在首版接管外部 Stack 或支持本地构建；账号是否需要仅 OIDC。节点数量、系统架构和典型配置样例用于收紧兼容范围与验证规模，目前不虚构上限或性能指标。
